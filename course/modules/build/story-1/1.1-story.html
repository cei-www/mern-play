Step 1.1: The story and what done looks like

Every feature starts as a user story: one sentence that says who wants what, and why.

ทุกฟีเจอร์เริ่มจาก user story ซึ่งเป็นประโยคเดียวที่บอกว่าใครต้องการอะไร และเพราะอะไร

As a user, I want to see my tasks in a list, so that I know what I have to do.

The story is finished when these acceptance criteria are true:

  • GET /api/tasks answers 200 with a JSON array of the tasks in the database.
  • Each task has its group name (or null when it has no group).
  • The newest task comes first.
  • The React page shows the list, with a "Loading..." text while it waits and an error message if the API fails.

You will build it from the bottom up: SQL, then the Express route, then the React page.

story นี้ถือว่าเสร็จเมื่อ acceptance criteria ต่อไปนี้เป็นจริงทั้งหมด:

  • GET /api/tasks ตอบ 200 พร้อม JSON array ของ task ในฐานข้อมูล
  • แต่ละ task มีชื่อ group (หรือเป็น null ถ้าไม่มี group)
  • task ใหม่สุดอยู่บนสุด
  • หน้า React แสดงรายการ โดยมีข้อความ "Loading..." ระหว่างรอ และแสดงข้อความผิดพลาดถ้า API ล้มเหลว

คุณจะสร้างจากล่างขึ้นบน: SQL ก่อน แล้วเป็น route ของ Express แล้วจึงเป็นหน้า React
