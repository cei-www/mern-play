Step 1.6: GET /api/tasks reads MySQL

Now the main route. It runs the LEFT JOIN query from step 1.2 and sends the rows as JSON. At the top of the file there is a constant SELECT_TASKS that holds the SELECT ... LEFT JOIN ... part, so you only add the ordering.

db.query returns [rows, fields]. You only need rows, so use array destructuring: const [rows] = ....

ถึงเวลาทำ route หลัก มันรัน query LEFT JOIN จาก step 1.2 แล้วส่งแถวที่ได้กลับเป็น JSON ที่ต้นไฟล์มีค่าคงที่ SELECT_TASKS เก็บส่วน SELECT ... LEFT JOIN ... ไว้แล้ว คุณจึงเพิ่มแค่การเรียงลำดับ

db.query คืนค่าเป็น [rows, fields] เราใช้แค่ rows จึงใช้ array destructuring: const [rows] = ...

Edit server/routes/tasks.js (in the Explorer: build › server › routes › tasks.js). Write the code between the comments @tutorial:begin s1-6-list-tasks and @tutorial:end s1-6-list-tasks.

router.get('/', async (req, res, next) => {
  try {
    const [rows] = await db.query(`${SELECT_TASKS} ORDER BY t.created_at DESC, t.id DESC`);
    res.json(rows);
  } catch (err) {
    next(err);
  }
});

Save the file. The newest task comes first because of ORDER BY t.created_at DESC.

บันทึกไฟล์ task ใหม่สุดมาก่อนเพราะ ORDER BY t.created_at DESC

Open /api/tasks

Hint

Three parts: await db.query(...) to read, res.json(rows) to answer, next(err) in the catch. A 500 answer means the SQL or the code has an error: look at the message with docker compose logs --tail 30 ws-main on your computer.
