Step 1.3: How an Express route works

Express waits for HTTP requests. A route says: "when a request with this method and this path arrives, run this function". The function receives the request (req) and sends the answer with the response (res).

Express รอรับ HTTP request route คือการบอกว่า "เมื่อมี request ที่มี method และ path นี้เข้ามา ให้รันฟังก์ชันนี้" ฟังก์ชันได้รับ request (req) และส่งคำตอบกลับด้วย response (res)

app.get('/api/health', (req, res) => {
  res.json({ status: 'ok' });   // sends JSON and status 200
});

Big apps split routes into files. A Router is a small group of routes. app.use('/api/tasks', tasksRouter) mounts it, so a route written as router.get('/') answers /api/tasks.

Reading the database takes time, so the route function is async and waits with await. If the database fails, try/catch passes the error on with next(err) and Express answers 500.

แอปใหญ่ ๆ จะแยก route ไว้หลายไฟล์ Router คือกลุ่ม route ย่อย ๆ app.use('/api/tasks', tasksRouter) นำมาต่อ ทำให้ route ที่เขียนว่า router.get('/') ตอบที่ /api/tasks

การอ่านฐานข้อมูลใช้เวลา ฟังก์ชัน route จึงเป็น async และรอด้วย await ถ้าฐานข้อมูลมีปัญหา try/catch จะส่ง error ต่อด้วย next(err) แล้ว Express ตอบ 500

router.get('/', async (req, res, next) => {
  try {
    const [rows] = await db.query('SELECT ...');   // rows is an array of objects
    res.json(rows);
  } catch (err) {
    next(err);
  }
});

The Express server restarts by itself every time you save a file in server. You do not restart anything by hand.

เซิร์ฟเวอร์ Express จะรีสตาร์ตเองทุกครั้งที่คุณบันทึกไฟล์ใน server ไม่ต้องรีสตาร์ตด้วยมือ
