Step 0.6: Wipe the code

From here on you write the app yourself. One command removes the code of every feature but keeps the files, the folders and the database. Open the terminal of the Editor tab (menu Terminal, then New Terminal) and run:

จากตรงนี้ไปคุณจะเขียนแอปเอง คำสั่งเดียวจะลบโค้ดของทุกฟีเจอร์ออก แต่ไฟล์ โฟลเดอร์ และฐานข้อมูลยังอยู่ เปิด terminal ของ tab Editor (เมนู Terminal แล้ว New Terminal) แล้วพิมพ์:

tutorial wipe

It asks you to confirm, then lists the files it changed. Open server/routes/tasks.js (in the Explorer: build › server › routes › tasks.js). Each place that was between two @tutorial comments now holds one line like this and two empty lines:

คำสั่งจะขอให้ยืนยัน แล้วแสดงรายชื่อไฟล์ที่เปลี่ยน เปิด server/routes/tasks.js ทุกที่ที่เคยอยู่ระหว่างคอมเมนต์ @tutorial สองบรรทัด จะเหลือบรรทัดแบบนี้ 1 บรรทัดกับบรรทัดว่าง 2 บรรทัด:

// @tutorial:begin s1-6-list-tasks
// TODO (s1-6-list-tasks): write your code here


// @tutorial:end s1-6-list-tasks

Each lesson tells you the file and the place. You write your code on the empty lines between the comments. Keep the @tutorial lines: the helper commands and the checks use them.

The app still starts. Open Swagger: GET /api/tasks now answers 404, and the React list is empty. Your data is untouched.

บทเรียนแต่ละ step จะบอกไฟล์และตำแหน่ง คุณเขียนโค้ดในบรรทัดว่างระหว่างคอมเมนต์ อย่าลบบรรทัด @tutorial เพราะคำสั่งช่วยเหลือและการตรวจใช้บรรทัดเหล่านี้

แอปยังรันได้ เปิด Swagger: GET /api/tasks จะตอบ 404 และรายการใน React ว่างเปล่า แต่ ข้อมูลยังอยู่ครบ

Hint

If the command says it must be run inside a module folder, add the module name: tutorial wipe --module build. Wiping twice is safe.
