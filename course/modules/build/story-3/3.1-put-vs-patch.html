Step 3.1: PUT or PATCH

You can change a task in two ways, and the HTTP method says which one you mean.

  • PUT replaces the whole task: you send every field. You will build this in Story 7.
  • PATCH changes a part of it: you send only what changes.

Marking a task as done changes only done (and the time it was completed), so it is a PATCH. The route is PATCH /api/tasks/:id/done and the body is { "done": true }.

แก้ task ได้ 2 แบบ และ HTTP method บอกว่าคุณหมายถึงแบบไหน

  • PUT แทนที่ทั้ง task: ส่งทุกฟิลด์ คุณจะทำใน Story 7
  • PATCH แก้บางส่วน: ส่งเฉพาะสิ่งที่เปลี่ยน

การทำเครื่องหมายว่าเสร็จเปลี่ยนแค่ done (กับเวลาที่ทำเสร็จ) จึงเป็น PATCH route คือ PATCH /api/tasks/:id/done และ body คือ { "done": true }

As a user, I want to tick a task as done, so that I can see my progress and find it later in the history.

Acceptance: done sets completed_at to now, "not done" sets it back to empty, an id that does not exist answers 404, and the page shows a checkbox.
