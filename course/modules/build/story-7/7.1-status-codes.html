Step 7.1: HTTP status codes

As a user, I want to fix a mistake in a task or delete it, and I want clear messages when something goes wrong.

The status code is the first thing a client reads. You have used these already:

CodeMeaningWhere you used it
200OKreading and updating
201CreatedPOST a task or a group
204No Content: done, nothing to send backDELETE (this story)
400The request is wrong (the caller can fix it)validation
404There is no such thingan id or a path that does not exist
500The server failed (the caller cannot fix it)an error in the database or the code

This story also gives every error the same shape, { "error": "text" }, so the page can always show data.error.
