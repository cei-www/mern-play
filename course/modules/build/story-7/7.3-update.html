Step 7.3: PUT /api/tasks/:id

PUT replaces the editable fields (title, priority, due date, group). The body has the same shape as for creating a task, so you can reuse validateTask from Story 2. That is the point of a function: one set of rules for two routes.

PUT แทนที่ฟิลด์ที่แก้ได้ (title, priority, due date, group) body มีรูปแบบเดียวกับตอนสร้าง task คุณจึง ใช้ validateTask ซ้ำ จาก Story 2 ได้ นี่คือประโยชน์ของฟังก์ชัน: กติกาชุดเดียวใช้กับสอง route

Edit server/routes/tasks.js (in the Explorer: build › server › routes › tasks.js). Write the code between the comments @tutorial:begin s7-3-update-task and @tutorial:end s7-3-update-task.

router.put('/:id', async (req, res, next) => {
  const id = Number(req.params.id);
  if (!Number.isInteger(id)) return res.status(400).json({ error: 'id must be a whole number' });
  const { error, value } = validateTask(req.body);
  if (error) return res.status(400).json({ error });
  try {
    await db.query('UPDATE tasks SET title = ?, priority = ?, due_date = ?, group_id = ? WHERE id = ?', [
      value.title,
      value.priority,
      value.dueDate,
      value.groupId,
      id,
    ]);
    const task = await findTask(id);
    if (!task) return res.status(404).json({ error: 'Task not found' });
    res.json(task);
  } catch (err) {
    if (err.code === 'ER_NO_REFERENCED_ROW_2') return res.status(400).json({ error: 'group_id does not exist' });
    next(err);
  }
});

Hint

Validate first (answer 400), then UPDATE ... WHERE id = ?, then read the task again with findTask and answer 404 when it is missing. This is the same shape as the PATCH route in step 3.3.

Solution

In server/routes/tasks.js, between the comments of s7-3-update-task:
