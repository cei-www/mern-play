Step C.4: Filter and sort UI: test behavior, not looks

SortBar in src/client/components/SortBar.jsx has two menus and calls onChange({ sort, order }). The point of this step is what you assert.

Good component tests describe behavior: what the user does, and what they see or what the component reports. Bad ones stick to details: a class name (.btn-primary), a position in the tree, the exact HTML. Such tests break when you restyle or tidy the page, though nothing is wrong, and then people stop trusting them. See the difference:

SortBar ใน src/client/components/SortBar.jsx มีสองเมนูและเรียก onChange({ sort, order }) จุดสำคัญของ step นี้คือ คุณ assert อะไร

test ของ component ที่ดีบรรยาย พฤติกรรม: ผู้ใช้ทำอะไร และเห็นอะไร หรือ component รายงานอะไร ส่วน test ที่แย่ยึด รายละเอียด: ชื่อ class (.btn-primary) ตำแหน่งใน tree หรือ HTML ตรงตัว test แบบนั้นล้มเมื่อคุณปรับสไตล์หรือจัดโค้ดใหม่ ทั้งที่ไม่มีอะไรผิด แล้วคนก็เลิกเชื่อมัน ดูความต่าง:

// Brittle: breaks when someone renames a class or moves a div.
expect(container.querySelector('.sort-bar select:nth-child(2)').value).toBe('desc');

// Behavior: the user chooses "Order: Descending" and the component reports it.
await user.selectOptions(screen.getByLabelText('Order'), 'desc');
expect(onChange).toHaveBeenCalledWith({ sort: 'priority', order: 'desc' });

Write the tests for the sort bar: it shows the current choice, and each menu reports its new value and keeps the other one (a classic bug is to forget it).

เขียน test ให้ sort bar: มันแสดงตัวเลือกปัจจุบัน และแต่ละเมนูรายงานค่าใหม่ และคงค่าของอีกเมนูไว้ (บั๊กคลาสสิกคือลืมส่วนนี้)

Create the file tests/SortBar.test.jsx (in the Explorer: unit › tests › SortBar.test.jsx; right-click the folder, then New File). Paste the code into it and save.

import { render, screen } from '@testing-library/react';
import userEvent from '@testing-library/user-event';
import { describe, expect, it, vi } from 'vitest';
import SortBar from '../src/client/components/SortBar.jsx';

describe('SortBar', () => {
  it('shows the current choice', () => {
    render(<SortBar sort="priority" order="desc" onChange={() => {}} />);

    expect(screen.getByLabelText('Sort by')).toHaveValue('priority');
    expect(screen.getByLabelText('Order')).toHaveValue('desc');
  });

  it('reports the new sort and keeps the order', async () => {
    const user = userEvent.setup();
    const onChange = vi.fn();
    render(<SortBar sort="created_at" order="desc" onChange={onChange} />);

    await user.selectOptions(screen.getByLabelText('Sort by'), 'title');

    expect(onChange).toHaveBeenCalledWith({ sort: 'title', order: 'desc' });
  });

  it('reports the new order and keeps the sort', async () => {
    const user = userEvent.setup();
    const onChange = vi.fn();
    render(<SortBar sort="priority" order="asc" onChange={onChange} />);

    await user.selectOptions(screen.getByLabelText('Order'), 'desc');

    expect(onChange).toHaveBeenCalledWith({ sort: 'priority', order: 'desc' });
  });
});
npx vitest run tests/SortBar.test.jsx
Hint

toHaveValue('priority') reads the chosen option of a menu. selectOptions takes the value or the visible text of an option.

Solution

In tests/SortBar.test.jsx (create the file):
