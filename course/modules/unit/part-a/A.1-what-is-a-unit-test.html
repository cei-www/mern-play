Step A.1: What a unit test is

A unit test is a small program that runs one piece of your code (a unit: usually one function or one component) with chosen input and checks that the result is what you expect. It runs in milliseconds, needs no database and no browser, and tells you which function is wrong when something breaks.

Tests come in sizes. Think of a pyramid:

  • Many unit tests at the bottom: fast, small, easy to read when they fail. This module.
  • Some integration tests in the middle: several parts together, for example the route and the database. You did these with tutorial check in module build.
  • A few end-to-end tests at the top: a whole system from the outside, slow. The Robot Framework tests of module api are of this kind.

Every good test has three parts, Arrange, Act, Assert:

unit test คือโปรแกรมเล็ก ๆ ที่รันโค้ดชิ้นเดียวของคุณ (หนึ่ง unit: มักเป็นหนึ่งฟังก์ชันหรือหนึ่ง component) ด้วยข้อมูลที่เลือกไว้ แล้วตรวจว่าผลลัพธ์ตรงกับที่คาด รันเสร็จในไม่กี่มิลลิวินาที ไม่ต้องใช้ฐานข้อมูลหรือเบราว์เซอร์ และเมื่อมีอะไรพัง จะบอกได้ว่า ฟังก์ชันไหน ผิด

test มีหลายขนาด ลองนึกเป็น พีระมิด:

  • unit test จำนวนมาก ที่ฐาน: เร็ว เล็ก อ่านง่ายเมื่อล้ม คือ module นี้
  • integration test บางส่วน ตรงกลาง: หลายส่วนทำงานด้วยกัน เช่น route กับฐานข้อมูล คุณทำแบบนี้ด้วย tutorial check ใน module build
  • end-to-end test ไม่กี่ตัว ที่ยอด: ทดสอบทั้งระบบจากภายนอก ช้า test ของ Robot Framework ใน module api เป็นแบบนี้

test ที่ดีมีสามส่วน คือ Arrange, Act, Assert:

it('adds two numbers', () => {
  // Arrange: get everything ready (input, fakes)
  const a = 2;
  const b = 3;
  // Act: run the one thing you test
  const result = add(a, b);
  // Assert: say what must be true
  expect(result).toBe(5);
});

The project. Open the Editor tab. The folder unit has two parts:

  • src: the code under test. A cleaned-up piece of the Task Manager: server logic in src/server and React components in src/client. You do not change it. (The checks tell you if you did.)
  • tests: empty. Everything you write goes here. The tool is Vitest; for components, Testing Library.

Take two minutes to open src/server/orderBy.js and src/server/validateTask.js (Explorer: unit › src › server). They are short. In the next steps you test them.

Two rules of the project: a file ending in .test.js runs in plain Node (for server code); a file ending in .test.jsx runs in a simulated browser (for components). Open the terminal of the Editor tab (it starts in the project folder). These commands exist:

โปรเจกต์ เปิด tab Editor โฟลเดอร์ unit มีสองส่วน:

  • src: โค้ดที่จะถูกทดสอบ เป็นส่วนของ Task Manager ที่จัดให้สะอาด: logic ฝั่ง server ใน src/server และ React component ใน src/client คุณไม่ต้องแก้ (ถ้าแก้ การตรวจจะบอก)
  • tests: ว่างอยู่ ทุกอย่างที่คุณเขียนอยู่ที่นี่ เครื่องมือคือ Vitest และ Testing Library สำหรับ component

ใช้เวลาสองนาทีเปิด src/server/orderBy.js และ src/server/validateTask.js (Explorer: unit › src › server) ไฟล์สั้นมาก step ถัดไปคุณจะทดสอบมัน

กฎสองข้อของโปรเจกต์: ไฟล์ที่ลงท้าย .test.js รันใน Node ธรรมดา (สำหรับโค้ดฝั่ง server) ไฟล์ที่ลงท้าย .test.jsx รันในเบราว์เซอร์จำลอง (สำหรับ component) เปิด terminal ของ tab Editor (เริ่มที่โฟลเดอร์โปรเจกต์) มีคำสั่งเหล่านี้:

npm test              # run every test once
npm run test:watch    # run again every time you save (press q to quit)
npm run coverage      # run every test and show which lines they touched
Hint

Nothing to do here but read. If a command is not found, check that the terminal is in the folder unit (the prompt shows it).
