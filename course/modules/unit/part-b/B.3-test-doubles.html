Step B.3: Test doubles: stub, mock and spy

Some code cannot run in a unit test: it needs a database, the network or the clock. createTask calls db.query, which in real life talks to MySQL. For a unit test you replace the part that is outside with a test double, a stand-in you control. Three kinds, all made with Vitest's vi:

  • Stub: gives a prepared answer. db.query.mockResolvedValue([{ insertId: 42 }]) says "when called, answer with this".
  • Spy: records how it was called, so you can check it afterwards: expect(db.query).toHaveBeenCalledWith(...), db.query.mock.calls[0].
  • Mock: a stand-in for a whole module. vi.mock('../src/server/db.js', () => ({ db: { query: vi.fn() } })) replaces the file for the code under test, and vi.fn() makes a function that is stub and spy in one.

What to remember: a double lets you test your code alone, fast and the same every time. The price: the double can be wrong about the real thing. That is why you also keep a few integration tests (the checks of module build).

The rule of thumb: replace what is slow, random or outside your control (database, network, time). Do not replace the code you want to test.

โค้ดบางอย่างรันใน unit test ไม่ได้: ต้องใช้ฐานข้อมูล เครือข่าย หรือนาฬิกา createTask เรียก db.query ซึ่งในของจริงคุยกับ MySQL สำหรับ unit test คุณแทนส่วนที่อยู่ข้างนอกด้วย test double ตัวแทนที่คุณควบคุมได้ มีสามแบบ ทำด้วย vi ของ Vitest ทั้งหมด:

  • Stub: ตอบคำตอบที่เตรียมไว้ db.query.mockResolvedValue([{ insertId: 42 }]) แปลว่า "เมื่อถูกเรียก ให้ตอบแบบนี้"
  • Spy: จดว่าถูกเรียกอย่างไร เพื่อให้ตรวจทีหลังได้: expect(db.query).toHaveBeenCalledWith(...), db.query.mock.calls[0]
  • Mock: ตัวแทนของทั้ง module vi.mock('../src/server/db.js', () => ({ db: { query: vi.fn() } })) แทนไฟล์นั้นให้โค้ดที่ทดสอบ และ vi.fn() สร้างฟังก์ชันที่เป็นทั้ง stub และ spy

สิ่งที่ต้องจำ: double ให้คุณทดสอบโค้ด ของคุณ โดด ๆ เร็ว และเหมือนเดิมทุกครั้ง ราคาที่จ่าย: double อาจเข้าใจของจริงผิด จึงควรเก็บ integration test ไว้บ้าง (การตรวจของ module build)

หลักง่าย ๆ: แทนสิ่งที่ ช้า สุ่ม หรือคุมไม่ได้ (ฐานข้อมูล เครือข่าย เวลา) อย่าแทนโค้ดที่คุณอยากทดสอบ
