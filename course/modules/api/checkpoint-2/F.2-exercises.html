Exercise 3 (harder): a keyword that compares the API with the database

Write the keyword Task Count Should Match Database in the resource file. It gets the list of tasks from the API, counts them, counts the rows of tasks with SQL, and fails when the numbers differ. Then write a test Api And Database Agree On The Task Count that uses it.

เขียน keyword Task Count Should Match Database ในไฟล์ resource มันขอรายการ task จาก API นับจำนวน นับแถวของ tasks ด้วย SQL และล้มเมื่อตัวเลขต่างกัน จากนั้นเขียนเทสต์ Api And Database Agree On The Task Count ที่ใช้มัน

Edit resources/api.resource (in the Explorer: api › resources › api.resource). First the keyword, at the end of the file.

Solution

In resources/api.resource, at the end:

Task Count Should Match Database
    ${response}=    GET    ${BASE_URL}/api/tasks
    ${api_count}=    Get Length    ${response.json()}
    ${rows}=    Query    SELECT COUNT(*) FROM tasks
    Should Be Equal As Integers    ${api_count}    ${rows}[0][0]

Create the file tests/08_checkpoint_2.robot (in the Explorer: api › tests › 08_checkpoint_2.robot). Then the test.

Hint

Get Length ${response.json()} counts the API items. Query SELECT COUNT(*) FROM tasks gives the database number as ${rows}[0][0]. Compare with Should Be Equal As Integers.

Solution

In tests/08_checkpoint_2.robot (the whole file so far):

*** Settings ***
Resource    ../resources/api.resource
Suite Setup    Connect To Test Database
Suite Teardown    Disconnect From All Databases
Test Teardown    Delete Test Tasks

*** Test Cases ***
Api And Database Agree On The Task Count
    Task Count Should Match Database

Exercise 4 (harder): create, delete, delete again

Write a test named Deleted Task Is Gone. It creates a task with the keyword Create Task (title starting with Robot ), deletes it and expects 204, deletes it again and expects 404, and finally reads it with GET and expects 404.

เขียนเทสต์ชื่อ Deleted Task Is Gone สร้าง task ด้วย keyword Create Task (title ขึ้นต้นด้วย Robot ) ลบมันและคาดหวัง 204 ลบ อีกครั้ง และคาดหวัง 404 และสุดท้ายอ่านด้วย GET และคาดหวัง 404

Edit tests/08_checkpoint_2.robot (in the Explorer: api › tests › 08_checkpoint_2.robot). Add at the end of the file.

Hint

The keyword DELETE works like GET. The second delete needs expected_status=404. The reference API has a hidden bug where deleting a missing task still answers 204; only the second delete notices it.

Solution

In tests/08_checkpoint_2.robot, at the end:

Deleted Task Is Gone
    ${id}=    Create Task    Robot delete me
    ${first}=    DELETE    ${BASE_URL}/api/tasks/${id}
    Should Be Equal As Integers    ${first.status_code}    204
    ${second}=    DELETE    ${BASE_URL}/api/tasks/${id}    expected_status=404
    ${read}=    GET    ${BASE_URL}/api/tasks/${id}    expected_status=404
  PASS  The keyword and the test compare the API count with the database
  PASS  The test "Deleted Task Is Gone" passes and catches a bad API
