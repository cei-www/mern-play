Step C.3: Test isolation

Tests that write data must not disturb each other, and must not touch your real data. Two habits make this safe:

  • A separate database. The reference API for this module uses taskapp_test, never taskapp (your app's data). You can destroy it and restore it with reset-db without any worry.
  • Each test cleans up after itself. A test must not depend on what another test left behind, and it must not leave rows that change the result of the next run. You will add a teardown in step C.5.

A test that passes only when it runs after another test, or only the first time, is called flaky. Flaky tests teach people to ignore failures.

เทสต์ที่เขียนข้อมูลต้องไม่รบกวนกัน และต้องไม่แตะข้อมูลจริงของคุณ นิสัยสองข้อทำให้ปลอดภัย:

  • ฐานข้อมูลแยก reference API ของ module นี้ใช้ taskapp_test ไม่ใช่ taskapp (ข้อมูลของแอปคุณ) คุณทำลายและกู้คืนด้วย reset-db ได้โดยไม่ต้องกังวล
  • เทสต์แต่ละตัวเก็บกวาดหลังตัวเอง เทสต์ต้องไม่พึ่งสิ่งที่เทสต์อื่นทิ้งไว้ และต้องไม่ทิ้งแถวที่ทำให้ผลของการรันครั้งถัดไปเปลี่ยน คุณจะเพิ่ม teardown ใน step C.5

เทสต์ที่ผ่านเฉพาะเมื่อรันหลังเทสต์อื่น หรือผ่านเฉพาะครั้งแรก เรียกว่า flaky เทสต์ที่ flaky สอนให้คนเมินความล้มเหลว
