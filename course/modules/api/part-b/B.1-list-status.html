Step B.1: GET /api/tasks: status and content type

A good API test checks more than "it answered". Start a new file for the tests that read tasks. The first test checks the status and the Content-Type header, so a client knows it receives JSON.

${response.headers}[Content-Type] reads one header. Should Contain checks that a text contains another (the header is application/json; charset=utf-8).

เทสต์ API ที่ดีตรวจมากกว่าแค่ "มันตอบ" เริ่มไฟล์ใหม่สำหรับเทสต์ที่อ่าน task เทสต์แรกตรวจ status และ header Content-Type เพื่อให้ client รู้ว่าได้รับ JSON

${response.headers}[Content-Type] อ่าน header หนึ่งตัว Should Contain ตรวจว่าข้อความหนึ่งมีอีกข้อความอยู่ข้างใน (header คือ application/json; charset=utf-8)

Create the file tests/02_tasks_read.robot (in the Explorer: api › tests › 02_tasks_read.robot) (right-click the folder in the Explorer, then New File).

*** Settings ***
Library    RequestsLibrary
Library    Collections

*** Variables ***
${BASE_URL}    http://localhost:3001

*** Test Cases ***
List Tasks Returns 200 And Json
    ${response}=    GET    ${BASE_URL}/api/tasks
    Should Be Equal As Integers    ${response.status_code}    200
    Should Contain    ${response.headers}[Content-Type]    application/json
robot --outputdir results tests/02_tasks_read.robot
Hint

You can run one file at a time: robot --outputdir results tests/02_tasks_read.robot. The headers of requests are case-insensitive.
