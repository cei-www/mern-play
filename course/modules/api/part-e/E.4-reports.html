Step E.4: Read the report in depth

When a test fails in a big suite you need to find the cause fast. Practice on purpose. Break one test and follow the clues:

  1. In tests/06_data_driven.robot change the expected status 400 to 200. Save.
  2. Run robot --outputdir results tests. In the terminal, find the failing lines: they name the test and the message.
  3. Open report.html, click the red test and then log.html. Open the failed keyword: you see the arguments it received and the exact message.
  4. Run again with more detail: robot --outputdir results --loglevel DEBUG tests. The log now has the response bodies.
  5. Put 400 back and run once more: everything is green.

Read from the bottom: the last keyword in the failed test is usually where the truth is.

เมื่อเทสต์ล้มในชุดใหญ่ คุณต้องหาสาเหตุให้เร็ว ฝึกโดยตั้งใจ ทำให้เทสต์หนึ่งตัวพังแล้วตามร่องรอย:

  1. ใน tests/06_data_driven.robot เปลี่ยน status ที่คาดหวังจาก 400 เป็น 200 บันทึก
  2. รัน robot --outputdir results tests ใน terminal หาบรรทัดที่ล้ม: บอกชื่อเทสต์และข้อความ
  3. เปิด report.html คลิกเทสต์สีแดง แล้วคลิก log.html เปิด keyword ที่ล้ม จะเห็น argument ที่มันได้รับและข้อความที่แน่นอน
  4. รันอีกครั้งด้วยรายละเอียดมากขึ้น: robot --outputdir results --loglevel DEBUG tests ตอนนี้ log มีเนื้อหาของ response
  5. เปลี่ยน 400 กลับ แล้วรันอีกครั้ง: เขียวหมด

อ่านจากล่างขึ้นบน: keyword สุดท้าย ของเทสต์ที่ล้มมักเป็นที่ที่ความจริงอยู่
